# 筛选子集排序合并回完整序列（Codex 提案 2026-08-27，2026-10-30 用户拍板采纳；含全量口径推广）

**排序规则**：用户在筛选/周期视图内重排时，不得只持久化可见子集、也不得为该视图建独立顺序。以用户完整序列为唯一事实源（canonical order），把可见的移动按锚点合并回去：

1. 从完整序列移除被移动项；
2. 在重排后的子集中找它前/后紧邻的可见项作锚点；
3. 按锚点插回完整序列，隐藏项相对顺序全部保留；
4. 向服务端提交完整 ID 序列 + 上下文/版本契约。

例：完整 `A,B,C,D,E`，可见 `A,C,E`，用户排成 `E,A,C` → 完整 `E,A,B,C,D`。单一事实源覆盖全部/周/月/标签等视图，防隐藏项丢失、409 范围错配、重渲染后排序跳回。

**同根因推广——业务判断与显示裁剪分离（2026-10-09 两缺陷实证）**：蒙版/风险等级/聚合指标等业务判断基于完整（全项目）数据集，筛选/裁剪只作用于展示；先裁剪再判断会漏边界情形（本期只剩未来节点的项目漏生成白色蒙版；筛选让实际逾期项目在聚合口径中降级为普通进展）。
