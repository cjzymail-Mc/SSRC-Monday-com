# Subplan 01：看板与视图可视化优先开发计划

## 1. 计划定位

本计划面向约 15 人的小型团队，部署于本地局域网。

产品建设以“看板功能模块”和“视图可视化模块”为最高优先级：先建立稳定、可扩展的看板数据模型，再让表格、Kanban、日历、时间线、图表和仪表盘共享同一套任务数据、字段、筛选与权限体系。

当前仓库已完成第一阶段实现并进入最终全局验收。本计划保留为架构与验收执行基线；模块定义以 `MONDAY_FEATURE_MAP.md` 为准。

## 2. 核心原则

1. 看板与视图优先，其他模块只优先建设其必要依赖。
2. 动态字段系统（B05）必须前置，避免不同视图各自维护固定字段逻辑。
3. 所有视图共享统一的数据、筛选、排序和权限模型。
4. 先完成稳定可用的核心流程，再增加高级可视化和自动化。
5. 局域网产品仍需具备登录、权限、备份、审计和基础安全，不能只实现界面。
6. 每一阶段都必须形成可独立验收、可供团队使用的版本。

## 3. 第一阶段：核心看板与基础视图（最高优先级，已完成候选）

### 3.1 阶段目标

让团队能够在多个看板中，通过自定义字段管理任务，并使用表格、Kanban 和日历视图完成日常协作。

### 3.2 看板与任务开发顺序

1. B01 看板管理：创建、复制、移动、归档、删除和恢复。
2. B02 分组管理：创建、重命名、排序、折叠、移动和删除。
3. B03 任务管理：新增、查看、编辑、复制、移动、归档和删除。
4. B05 动态字段系统：字段定义、增删、排序、配置和数据存储。
5. B06 基础字段：文本、数字、状态、人员、日期、复选框、标签和链接。
6. B11 任务排序：组内拖拽、跨组移动，并为跨看板移动预留模型。
7. B13 筛选与排序：多条件组合、排序和筛选状态管理。
8. B14 任务详情页：字段、描述、评论和活动记录。
9. B12 批量操作：批量修改、移动、归档和分配。
10. B17 回收站与恢复：软删除、保留期限和恢复。

### 3.3 基础视图开发顺序

1. C01 表格视图：行列编辑、列宽、冻结和字段呈现。
2. C02 Kanban：按状态或人员分列，拖拽时更新对应字段。
3. C03 日历视图：按日期展示任务，并支持拖动修改日期。
4. C10 保存视图：保存视图类型、筛选、排序和显示配置。

### 3.4 必要支撑模块

- A01 用户登录：账号密码、登录退出和会话管理。
- A02 用户与团队：成员资料、启用和禁用。
- A03 基础角色权限：管理员、成员和只读。
- A04 工作区：工作区及成员关系。
- A05 看板权限：开放、私有和指定成员访问。
- D01 任务评论：先完成新增和展示，并为回复、编辑和删除预留结构。
- D07 活动记录：记录任务字段变化、移动和评论行为。
- M01 局域网部署：稳定启动、固定监听地址和部署说明。
- M03 数据备份：自动备份、保留策略和恢复验证。
- M06 基础安全：密码哈希、会话安全、CSRF/XSS 防护和输入校验。
- M08 数据保留：归档、软删除和永久删除策略。

### 3.5 第一阶段验收标准

- 管理员可以维护成员、工作区、看板和权限。
- 成员可以完整管理分组、任务和基础自定义字段。
- 表格、Kanban 和日历视图展示同一份任务数据。
- 在任一视图中修改任务后，其他视图能够得到一致结果。
- 支持多条件筛选、排序及保存个人或看板视图。
- 支持拖拽排序、跨组移动和常用批量操作。
- 任务详情能够展示字段、评论和活动历史。
- 删除的数据可以在保留期限内恢复。
- 数据库可自动备份，并完成至少一次恢复验证。

## 4. 第二阶段：高级看板与可视化

### 4.1 阶段目标

补足层级、关系、排期和跨看板分析能力，使系统达到实用的轻量 Work Management 水平。

### 4.2 看板增强开发顺序

1. B04 子任务。
2. B07 高级字段：时间线、评分、文件、邮件和电话等。
3. B10 依赖关系：前后置任务、阻塞状态和日期联动。
4. B08 关系字段：看板关联、任务关联、镜像字段和双向关系。
5. B16 Excel/CSV 导入导出。
6. B15 看板与项目模板。
7. B09 公式、汇总、进度和条件计算字段。

### 4.3 视图增强开发顺序

1. C04 时间线视图。
2. C07 图表视图。
3. C11 跨看板仪表盘。
4. C12 仪表盘组件。
5. C05 甘特图。

甘特图必须安排在时间线、依赖关系和里程碑模型稳定之后，避免重复开发排期逻辑。

### 4.4 协作与运行增强

- A07 通知中心。
- A09 全局搜索。
- D02 @提及。
- D05 文件附件。
- D08 任务订阅。
- M04 WebSocket 实时同步与基础冲突处理。
- M05 操作审计。
- M10 移动端响应式适配。

### 4.5 第二阶段验收标准

- 支持子任务、任务依赖及跨看板关系。
- 时间线与甘特图可以基于同一套日期和依赖数据排期。
- 图表和仪表盘能够跨看板汇总数据。
- 支持模板和可靠的 Excel/CSV 导入导出。
- 多人修改能够近实时同步，关键操作可审计。
- 桌面端和常用移动端尺寸均可完成核心操作。

## 5. 第三阶段：管理分析与效率提升

第三阶段依据前两阶段的真实使用反馈择优开发，不默认一次性全部实现。

推荐顺序：

1. C06 工作负载。
2. C13 报表导出。
3. E01 项目管理。
4. E03 目标与 OKR。
5. E04 里程碑。
6. E05 工时记录。
7. E09 风险管理。
8. G02 状态自动化。
9. G03 日期提醒和周期任务。
10. G06 自动化执行记录。
11. F01 表单设计器。
12. F03 匿名表单提交。
13. H03 Webhook。

自动化优先实现少量高频规则：

- 状态变化时通知负责人。
- 到期前提醒及逾期提醒。
- 任务完成后移动到指定分组。
- 新任务按规则自动分配。
- 按周期自动创建任务。

## 6. 明确延后模块

以下模块成本较高，且与当前核心需求关联较弱，暂不进入前三阶段的默认范围：

- D09、D10：Workdocs 与文档实时协作。
- G07：复杂可视化工作流。
- H04～H11：邮件、日历、即时通信、云盘、Git、连接器、插件和应用市场。
- I 系列：CRM 产品模块。
- J 系列：monday Dev 产品模块；若团队以软件研发为主营业务，可单独提前评估 J01～J05。
- K 系列：monday Service 产品模块。
- L01～L08：AI 与智能能力。
- M07：SSO/LDAP。
- M11、M12：原生移动 App 和完整离线能力。
- C08、C09：文件视图和地图视图。
