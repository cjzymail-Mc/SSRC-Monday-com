## 1. 产品目标与边界

在已交付的 Flowboard 上叠加鞋类研发项目的**时间节点编辑 + 单项目/多项目仪表盘**，服务约 10～15 人的局域网团队、约 10 个并行项目。

- 网页内提供类 Excel 编辑器；Excel 只作导入导出。
- 不接 Google 文档，不另做独立产品。
- 不扩成完整项目管理套件；不做 OKR、工时、预算、资源负载、审批等。
- 当前只做需求和静态原型；用户确认前不改主程序和数据库。

## 2. 已确认的业务模型

### 六阶段与节点

- 固定阶段：`创意 → 设计 → 开发 → 测试 → 量产 → 应用迭代`，不可增减改序。
- 一行一个单日里程碑节点；每个节点必须有阶段和节点名称。
- 阶段业务顺序固定，但日期允许重叠，仪表盘必须真实表达并行。

### 源数据表

当前推荐并已在 mock 中采用：

```text
项目名称｜项目阶段｜轨道｜项目节点｜日期｜时间间隔｜状态｜备注
```

- 用户日常只编辑一个【日期】，不再使用计划/实际双列。
- 【轨道】第一版只有 `主线 / 并行`。
- 两条轨道共用同一套节点、日期、间隔字段，不设置两套重复列。
- `initial_date` 仅在系统内部保存：新节点首次保存时自动建立；普通用户无感，管理员只能以审计方式纠正首次录错。
- 不强制填写修改原因；需要说明时使用现有【备注】列。

### 双轨日期与间隔

```text
主线：A → B → C
并行：P1 → P2 → P3
```

- 【间隔】只有一列，表示“当前节点与**同轨道上一节点**的日期差”。
- 每条轨道首节点的间隔为空。
- 改 B 日期：重算 B 间隔，只顺延 C 及后续主线节点。
- 改 B 间隔：重算 B 日期，只顺延 C 及后续主线节点。
- 并行轨完全沿用相同规则；改 P2 只影响 P3 及后续并行节点。
- 主线与并行互不计算间隔、互不顺延。
- 只改日期则日期优先；只改间隔则间隔优先；两者同时改则日期优先并覆盖重算间隔。
- 后续节点整体平移，后续各段原间隔保持不变；保存后提供一次撤销。
- 删除节点不移动其他日期，只重算该轨道合并后的间隔。

### 排序

编辑器用独立按钮切换：

1. 按日期排序（默认）。
2. 按六阶段分组，阶段内按日期升序。

排序只改变显示，不修改日期、间隔或审计数据。每个节点的间隔始终根据本轨道真实时间前驱计算。

## 3. 仪表盘与视觉

- 两种仪表盘：单项目、全部/多选项目。
- 使用共享的绝对日历标尺和红色今日线。
- 六阶段使用稳定专属色：当前候选为紫、蓝、青、橙、绿、金。
- 时间轴使用连续条形；条形已拍板为 **2px 小圆角矩形**。
- 单项目完整展示主线和并行轨。
- 多项目默认最多显示两轨；当前业务假设现实中最多主线 + 并行双轨。
- 不用透明混色承担主要信息表达。

## 4. 轻量延期复盘方向

不建设企业级 baseline、定期快照或复杂 BI：

- 日常界面只展示当前有效日期，不满屏标红延期。
- 内部保留 `initial_date`、当前 `date` 和结构化修改活动。
- 级联顺延记录为一次操作批次，区分直接修改与自动影响。
- 第一版复盘只需按单/多项目筛选，查看初始日期、当前日期、净变化天数、直接修改次数和修改历史。

此处的“延期”严格说是“相对首次录入日期的变化”，这是当前轻量方案可接受的限制。

## 5. 权限与工程红线

- 注册用户可增删改；非注册用户只读；暂不做项目级细分权限。
- 权限必须服务端执行。
- 所有修改可追踪，删除优先软删除。
- schema 迁移前必须备份且可恢复；不得破坏第一阶段旧数据。
- 后续每个实现检查点必须同时包含数据层、API、可操作 UI、测试和文档。
