## 1. 产品定位

在已交付的 Flowboard 之上，新增一套面向约 15 人鞋类研发团队的**项目时间节点管理与组合仪表盘**。

它首先解决三个问题：

1. 团队能像编辑 Excel 一样快速维护频繁变化的项目节点日期。
2. 单个项目能把六阶段、主线/并行节点和当前日期放在同一条绝对日历轴上理解。
3. 多个项目能在共享日历标尺下横向对齐，让用户快速判断当前阶段、临近节点和轻重缓急；延期历史按需进入轻量复盘。

本 feature 是 Flowboard 上的聚焦能力扩展，不另做独立产品，也不把 Flowboard 扩成完整的企业项目管理套件。

## 2. 目标用户与权限基线

- 主要用户：约 15 人鞋类研发团队，管理跑鞋、篮球鞋、羽毛球鞋等约 10 个并行项目。
- 复用 Flowboard workspace 角色：admin（当前 1 名）与 member（多名注册成员）；本团队暂不引入 viewer，不新建角色体系。
- 查看：单项目/全项目仪表盘与时间表编辑器对所有注册成员（admin + member）开放；未登录不可见；不引入访客/公开分享机制。
- 写权限（项目级创建者权限，2026-08-14 用户拍板纳入）：workspace admin 可修改/拖动所有项目时间轴；member 只能修改/拖动自己创建的项目时间轴（created_by = 自己）。
- 权限技术契约（2026-08-14 冻结，问卷 Q20–Q22）：created_by 由系统在首次创建时写入，此后任何人（含 admin）不可修改；initial_date 例外纠正权仅限 workspace admin（member 录错须找 admin，纠正留审计）；Excel 导入的项目 created_by = 导入操作者，第一版不做「指定创建者」功能。
- 项目实体入口（2026-08-18 用户 B5c=b）：admin/member 均可网页新建项目，created_by=当前操作者；仅 admin 可软删；v1 不提供项目改名或恢复入口。Excel 导入继续作为批量创建入口。
- 标签权限例外（2026-08-24 用户 Q4/Q5 拍板）：标签目录与项目标签归属属于 workspace 共享元数据；所有注册 admin/member 均可为任意活跃项目添加/移除标签，并可创建、改名标签，仅 admin 可删除标签。该例外**不授予**项目名称、节点、日期、状态、备注等项目内容写权限，也不扩展为通用字段级权限或 ACL。
- 权限必须由服务端执行；只在前端隐藏按钮不构成授权控制。

## 3. 统一业务模型

### 3.1 项目生命周期

所有项目严格使用以下六个一级阶段，顺序固定：

```text
创意 → 设计 → 开发 → 测试 → 量产 → 应用迭代
```

本 feature 内不允许用户新增、删除、重命名或调整六阶段顺序。

### 3.2 时间节点

- 每个项目有独立的时间轴和不同的起止日期。
- 一行代表一个任务节点。
- 每个节点必须属于一个项目，并同时具备“项目阶段（一级标签）”和“项目节点（二级标签）”。
- 节点是单个日期上的里程碑，不是有起止日期的任务条。
- 必要业务字段为：`项目名称｜项目阶段｜轨道（主线/并行）｜项目节点｜日期｜时间间隔｜状态｜备注`。
- 主线与并行各自形成独立线性链，共用同一套节点/日期/间隔字段；两轨互不计算间隔、互不顺延。
- 将来可以通过受控变更增加字段，但不能破坏既有数据和导入导出兼容性。

### 3.3 日期、修改历史与轻量复盘

- 日常正式使用一个当前有效【日期】列，不使用计划日期/实际日期双列。
- 每次直接修改和系统级联顺延必须进入修改历史，并能区分直接编辑与自动影响。
- 用户始终只操作一个日期字段；新插入节点第一次保存时，系统无感写入该节点的 `initial_date`。
- 普通用户不能修改 `initial_date`；管理员可在首次录错时通过例外入口纠正，并留下审计。
- 不新增修改原因字段或强制弹窗；解释性信息继续写入既有【备注】列。
- 第一版不建设命名基线、定期快照或复杂版本系统；节点内部保留首次保存的 `initial_date` 与当前 `date`，并复用结构化活动记录中间修改。
- 日常仪表盘不默认展示历史延期天数；延期分析进入一个按需打开、可筛选单项目或多项目的轻量复盘页面。

### 3.4 共享标签与用户个人顺序（2026-08-24 新增）

- 标签目录及“项目 ↔ 标签”多对多归属在 workspace 内全员共享；一个项目可以拥有多个标签。
- 标签使用稳定 ID，改名不得丢失归属或个人顺序；标签删除优先软删除，只停用该标签关系与有效排序，不删除项目本体或其他标签关系。
- “全部”“未分类”为系统虚拟入口，不创建普通标签实体：“全部”包含所有活跃项目，“未分类”只包含没有任何活跃普通标签的项目。
- 【我的项目】仍严格派生自 `created_by = 当前用户`，不新增负责人、参与人或项目角色模型。
- 个人顺序与共享标签严格分层：每位用户在【我的项目】、“全部”“未分类”及每个普通标签下分别拥有独立顺序；任何用户的排序不影响其他用户。
- 未建立个人位置的新项目追加到当前上下文末尾；项目移出标签后旧位置不再生效，重新加入按新项目追加末尾。

## 4. 本轮必须交付

### 4.1 类 Excel 时间表编辑器

- 在网页内完成节点表的查看、增加、修改和删除。
- 行列结构明确，支持高频日期调整，降低现有 Flowboard 编辑时间节点的操作成本。
- 支持一个当前有效日期字段的快速编辑。
- 支持按需显示自动计算的时间间隔，并允许通过手改间隔触发受控的后续日期顺延；顺延一直影响到项目末节点，后续各段间隔保持不变，保存后提供一次撤销。
- 日期与间隔采用本次编辑字段优先级：只改谁就以谁为输入；两者同时修改时日期优先，并自动更正间隔。
- 系统内部间隔始终按日期时间链计算；编辑器支持“按日期（默认）/按六阶段分组”两种显示排序，切换排序不得改变日期、间隔或审计数据。
- 主线与并行各自维护独立日期时间链，共用同一【间隔】列；间隔与顺延只在本轨道内生效，两轨互不影响。
- 删除节点不移动其他日期，只重算合并后的相邻间隔。
- 提供清晰的保存、校验、错误反馈和只读状态。
- Excel 作为导入/导出格式；Google 文档不作为数据源或编辑器。

### 4.2 单项目仪表盘

- 展示一个项目的完整六阶段时间轴和全部节点。
- 使用绝对日历标尺和“今天”标记。
- 六阶段拥有稳定且可区分的专属颜色。
- 默认展示当前有效日期，不让普遍存在的历史延期标记淹没日常判断。
- 能识别当前所处阶段/附近节点和延期情况。
- 与该项目的节点清单表形成清晰、可直接编辑的组合体验。
- 轨道行模型（2026-08-18 拍板）：默认固定「主线/并行」两行，行内阶段重叠通过展开按钮拆分（展开后每阶段独占一行）；取代早期「按重叠自动分轨」方案。
- 未展开时，仅重叠段上下分半渲染，非重叠段保持满高；六阶段原色不混色、不遮挡（2026-08-18 拍板）。
- 鼠标滚轮以指针日期为锚点做横向缩放；按住时间画布空白处只允许左右拖动，纵向位置不变。最细窗口沿用 14 天，范围钳制在本项目节点边界±30天。
- 正在进行中的项目以红色今天线分界：今天左侧整体覆盖 70% 白色蒙版，今天右侧保持六阶段原色；今天线从日历顶部贯穿且位于蒙版与日历标签之上。

### 4.3 全项目仪表盘

- 支持查看全部项目或多选部分项目。
- 每个项目一条泳道（泳道 = 项目容器，默认内含主线/并行两行，见本节末两条 2026-08-18 拍板），在共享的绝对日历标尺上横向对齐。
- 用相同的六阶段颜色语义表达各项目进展。
- 红色今日线贯穿所有泳道。
- 默认展示当前有效日期，不让普遍存在的历史延期标记淹没日常判断。
- 支持用户快速识别临近节点、延期项目、当前阶段和轻重缓急（2026-08-18 拍板）：顶部项目多选筛选 + 排序下拉（按开始日期 / 当前阶段先后 / 最近临近节点 / 逾期未完成节点数），行内只用克制小色点提示（橙 = 本周内有节点，红 = 有逾期未完成），不染整条泳道、不引入手动优先级字段。（⬆ 2026-08-18 门 3 问卷 D10 修订：橙点窗口由「7 天内有节点」改为「**本周（周一~周日，含今天所在自然周）内有未完成节点**，含本周已过去的天；红点不变；红橙可并存、红左橙右」——修订者为 Q5 原拍板人本人，覆盖注记见 `3-UX_DETAIL_REQUIREMENTS.md` §0 记录 5，细则见 `archive/5-GATE3_UNIT1_DECISIONS.md` §0 第 6 条。）
- 阶段业务顺序固定，但不同阶段日期允许重叠；仪表盘必须真实表达并行状态，不得通过修改日期或混合阶段颜色掩盖重叠。
- 每项目默认主线/并行两行（与单项目同一行模型），行内阶段重叠通过展开按钮拆分；未展开时仅重叠段上下分半（2026-08-18 拍板）；时间条统一使用 2px 小圆角矩形。
- 标签导航一次只进入“全部 / 未分类 / 一个普通标签 / 已归档项目”中的一个上下文；同一项目不会因多标签在当前大图重复出现。【已归档项目】是高优先级虚拟系统标签，归档项目不得出现在前三类 active 上下文。
- 排序下拉新增“自定义顺序”并作为默认；只有自定义模式允许上下拖拽并保存当前用户的当前上下文顺序。原四种自动排序完整保留、只读零写入，切换回自定义后恢复个人顺序。
- 项目多选筛选或搜索生效时禁用拖拽，并明确提示清除临时筛选后再调整完整顺序；自动排序或临时筛选不得覆盖已保存的个人顺序。
- 当前标签中的拖拽只修改当前用户个人顺序，不修改共享标签归属；其他标签与其他用户顺序保持不变。
- 全项目共享大图的绝对范围取当前标签上下文所有节点最早/最晚日期并向两端各扩 30 天；首次适配全部，最细可缩放到 14 天。
- 时间标尺源自 E 分层方案，当前按 2026-08-25 覆盖只保留彩色年/月/日层并移除季度层；节点拖动采用 D4（只强化原绝对标尺，松手即消失）；画布移动采用 P1（时间图左键横纵抓取，节点与控件排除，只改变抓手光标）。

## 6. 标准推进主线与阶段门

> 2026-09-04 进度重基线：下列推进主线已经走完；第 7 阶段的人工验收随正式上线确认完成，第 8 阶段主体已完成并进入生产运行。各技术冻结文档中的 `WAIT_*` 仅描述当时交付点，不再是当前状态。

```text
产品主线冻结
      ↓
业务规则与关键用户旅程确认
      ↓
低成本 UX 原型验证
      ↓
视觉方向确认
      ↓
技术方案、数据与 API 契约
      ↓
纵向切片开发
      ↓
集成测试、视觉收口与真实数据用户验收
      ↓
备份、迁移、部署与运行收口
```

### 阶段门 1：业务规则可实现

进入技术设计前，至少确认：日期顺延规则、状态列语义、编辑器关键操作、仪表盘的判断任务和 Excel 输入输出边界。

### 阶段门 2：原型可用

进入正式编码前，用户应能通过与问题匹配的原型完成代表性任务，并确认页面结构、交互方式和主要视觉方向。结构比较可用静态稿；密度、手势、视角记忆、连续切换等体验项须使用代表性数据下的可交互原型或隔离试用。此时确认“避免胶囊化”等方向，不必过早锁死具体圆角、色值和字号像素。

### 阶段门 3：技术方案安全

编码前完成数据模型、API、服务端权限、审计、并发、迁移、备份恢复和旧功能回归策略评审。

### 阶段门 4：纵向切片验收

每个开发检查点必须同时包含数据层、API、可操作 UI、测试和文档。单独完成静态页面、数据库或接口均不算检查点完成。

### 阶段门 5：可上线

真实数据关键旅程、权限、导入导出、日期计算、两类仪表盘、最终视觉人工验收、迁移恢复和第一阶段回归全部通过，才允许进入部署收口。

> 当前结果（2026-09-04）：该门已通过。系统已正式上线、真实库已部署并持续产生业务数据；上线后的修复和视觉/拖拽升级属于生产反馈迭代。

## 7. UI / UX 决策原则

UI 讨论贯穿全过程，但关注点分层：

1. 原型阶段先确认信息层级、编辑效率、操作反馈和防错。
2. 交互稳定后确认颜色体系、圆角倾向、密度和信息层级等视觉方向。
3. 集成和用户验收阶段基于真实数据集中完成具体色值、圆角、字号、行高、间距和响应式的最终美化收口，不无依据推翻核心交互。

当前静态样图只是验证工具，不是最终视觉规范。条形圆角已冻结为 2px 小圆角（2026-08-18）；剩余像素项（精确色值、条形粗细、字号、行高、留白）按本节第 3 条留集成验收期基于真实数据收口。

### 7.1 当前生产 as-built UI 基线（更新至 2026-09-04）

- 时间管理壳层不再提供“项目分组逐项目直达”，经典看板保持不可达；侧栏为可持久化的 248↔64px 中部悬浮轨，收起按钮固定在浏览器视口中线，不随项目数量或滚动位置移动。2026-08-31 起暂时隐藏【回收站】入口：现有回收站只覆盖旧版看板/分组/任务，尚未覆盖时间管理项目；底层旧 API 与项目软删除数据均保留。
- 全项目页保留标签、日期范围、年/月/日标尺、滚轮缩放、P1/D4 与可见全屏入口；标题/数量、项目筛选、排序、适配/加减缩放、排序提示、画布说明和季度层保持隐藏。全屏切换标签不退出全屏。
- 归档操作入口仅保留在单项目仪表盘的项目菜单；全项目行与时间表编辑器均不渲染【归档项目】。
- 单双仪表盘在既无草稿也无当前会话撤销时不渲染常驻【撤销/放弃/更新】操作条；形成日期/状态本地草稿后主动显示，放弃后消失。全项目项目名称列的右键菜单始终保留【撤销】，无当前会话可撤销提交时为灰色禁用态，有可撤销提交时才启用。
- 全项目项目名称列右键菜单固定两项：【在单仪表盘中查看】、【撤销】。前者进入单项目并把返回目标记为全项目，左上角显示【← 返回】；从我的工作等其他入口进入时仍显示【← 我的工作】。切换单项目/时间表编辑器页签不丢失返回目标；两种按钮均使用方案 D 箭头回弹悬停动画。
- 全项目左侧项目列及“项目”表头内的普通滚轮只纵向滚动项目列表，不改变 `viewportDays`；只有右侧日期/轨道画布内的滚轮执行时间轴缩放。
- 全项目滚轮缩放以当前 DOM 的真实时间绘图区和已渲染中心为坐标真源，不使用固定项目列宽或未夹取的旧视图中心；普通/全屏切换及各缩放档位下，指针日期应稳定在 1 天误差内。
- 单双仪表盘共用按每日像素宽度降级的无碰撞日期标尺；今天线从日历顶部贯穿，进行中项目今天左侧为 70% 白色蒙版；密集节点按 `<18px` 折叠为 5px 中性点。
- 单项目只允许横向缩放与横向抓取。单双仪表盘不读写视角记忆；进入页面或切换项目/标签后恢复完整范围，当前页内临时缩放与拖拽仍有效。
- 聚焦全项目中的一个项目后，为每个节点显示名称和日期旗标；未聚焦项目保留紧凑节点与 tooltip。单项目默认显示旗标，周/月视图复用同一行为；密集旗标按可用宽度自适应隐藏，首尾与精确 hover/focus/右键命中保持可用。
- 从节点或旗标右键选择拖拽模式后，节点、旗标、引线和命中面同步红色强调；可从节点或旗标直接拖动。松手形成草稿后强调持续到【更新】或【放弃】，切换页面/项目时清除未发生拖动的瞬时选择。
- 首页团队项目每成员默认最多显示 10 个并可展开；最新动态只显示动作与一条核心摘要，不输出 raw/JSON。
- 本小节是当前 UI 执行真源；与早期问卷、静态稿或 `14-`/`15-` 的阶段性描述冲突时，以本小节为准。这里记录的是已上线后的现行行为。

## 10. 纠偏检查

每次制定计划、调整原型、开始检查点或准备验收时回答：

1. 当前工作是否直接提高节点编辑效率或项目时间判断效率？
2. 是否让编辑器、单项目和全项目仪表盘共享同一数据与规则？
3. 是否把尚未确认的样图细节误写成冻结需求？
4. 是否把完整项目管理或其他未来功能偷偷纳入 feature01？
5. 是否省略服务端权限、审计、迁移、备份、恢复或测试？
6. 是否保护第一阶段既有功能和旧数据？
7. 当前成果是否有可操作证据和明确验收标准？
8. 团队共享标签归属与用户个人顺序是否使用独立数据、端点和权限，避免串写？
9. 自动排序或临时筛选是否可能覆盖个人顺序？删除/移除标签是否可能影响项目本体或其他标签？
10. 归档是否仍是独立系统状态、服务端鉴权与只读，而没有滑向普通标签、删除或自动任务？

任一答案表明偏离时，先修订需求、原型或计划，再继续。
