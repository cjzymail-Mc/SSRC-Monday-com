§1 现实同类系统的通行架构（借鉴来源）

系统它的结构值得我们借鉴的点
Monday.comHome（个人聚合）→ 板（项目）为主体；Dashboards 是独立顶层对象，可跨板聚合①「全局仪表盘」独立成顶级入口，只做一个；②个人主页只做聚合提醒，不承载管理
Jira项目 = 容器，容器内一排视图标签（Roadmap / Board / Backlog / Reports）；全局 Dashboards 另设时间轴/仪表盘是项目的「视图标签」，不是独立菜单——本项目最该抄的一条
AsanaHome 卡片聚合；项目内 List / Board / Timeline 标签切换；Portfolios 做全局同一份数据、多个视图：列表编辑与时间轴仪表盘是同一项目页的两个标签
Linear侧边栏极简：个人视图 / 团队 / 项目树；项目内 Overview / Roadmap 标签侧边栏只放「我的工作 + 项目 + 一个全局视图」，克制不膨胀
MS Project打开项目 = 打开甘特图本体；Roadmap 聚合多项目并排时间轴就是项目的第一公民（不是附属报表）——与你们「Excel 大表 → 时间轴」的心智一致

三条共同规律（行业共识）：
① 时间轴编辑器和单项目仪表盘几乎总是项目容器内的两个视图标签，而不是两个各自独立的菜单页；
② 跨项目聚合视图独立顶层、且只有一个（全项目仪表盘），不与个人主页混放；
③ 个人主页（我的工作）只做「我相关的项目 + 提醒 + 入口」，绝不长成管理后台。
