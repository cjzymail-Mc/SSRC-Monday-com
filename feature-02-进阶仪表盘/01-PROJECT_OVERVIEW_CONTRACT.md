## 目标与范围

在「我的工作」增加「项目总览」子入口。用户能迅速了解需关注的项目、项目创建者、当前阶段、下一未完成节点、日期、逾期及近期完成情况。复用已有项目、六阶段、主线/并行节点、时间表编辑器和单项目仪表盘。

采用一项目一行，默认全部活跃项目、本周范围、关注未完成节点。分组为「需要关注」（筛选后含逾期或今日未完成节点）和「近期推进」，紫/粉组头与细左边框。项目只进入一组；展开显示筛选命中的节点。可选显示已完成节点，以了解近期产出；选择全部日期可查看无近期节点/无节点/全部完成项目。默认本周同时纳入更早逾期节点，避免隐藏风险。

筛选：本周 / 本月 / 未来30天 / 全部日期；全部 / 我的（created_by=当前用户）；项目/节点/备注搜索；阶段、轨道、未完成/含已完成。结果数量、有效节点完成比例、展开明细均基于同一筛选集。进度明确标为「有效节点完成」，不冒充时间自然流逝完成度。项目当前阶段复用服务端既有指标，节点所属阶段单列。下一未完成节点取全项目服务端时间排序最早未完成节点（包括逾期），同日主线/并行全部可见，不虚构持续时间。

展开、折叠、筛选及滚动在当前会话中保留；进入既有单项目仪表盘/时间表后提供「返回项目总览」，返回刷新真实数据。原有未提交草稿离页确认继续生效，取消保持原页面。我的项目表示创建关系；成员列标注「创建者」，不新增负责人/任务分配。

## 数据、权限及工程边界

- 新增只读 `GET /api/workspaces/{id}/timeline/overview`，查询参数采用严格枚举并拒绝未知参数。登录、工作区成员权限沿用 TimelineService；viewer 按 feature01 基线拒绝。admin/member 可读全部，编辑仍由原批量写 API 服务端执行 admin/created_by 权限。
- 查询同时排除软删、归档项目和软删节点。不建新 schema，不落第二份派生状态；采用权限校验+批量项目/节点查询，复用 `_view` 的 server_today、状态与阶段指标，整个读取使用同一 SQLite 快照和上海自然日期。
- 空项目、无近期节点、全部完成、无下一未完成节点、无备注分别准确呈现。未完成逾期计数与筛选统计分别标注，禁止误算或泄漏其他工作区数据。
- 只使用现有 Python/SQLite/原生 JS/CSS，无外部服务或框架。新增静态资源加入 server.py 默认拒绝清单。
- 保护本轮前未提交改动；基线保存在 `team-progress/verification/20261008-feature02/baseline/`。冻结/归档资料只读。真实 flowboard.db 不写，不 commit/push，不发布部署，不改机器配置。
