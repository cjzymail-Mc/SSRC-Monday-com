# Flowboard 全项目持续开发总任务（看板与可视化主线）

## 1. 总任务

持续建设 Flowboard：一个面向约 15 人小型团队、部署于本地局域网的自托管协作看板。

本轮产品目标不是复刻完整 monday.com 产品族，而是集中完成：

1. 稳定、灵活的看板与任务管理。
2. 共享统一数据模型的表格、Kanban、日历及高级可视化。
3. 支撑 15 人团队可靠使用所必需的权限、协作、实时同步、安全、备份和移动适配。

本文件是 double-session 的全局冻结任务，不是单个迭代任务。coder 可以分检查点实现，planner 可以分检查点审核，但单个检查点通过不代表全局完成。

只有“全局 done_when”全部满足，planner 才能调用 `Done`。在此之前：

- coder 完成当前检查点后交给 planner；
- planner 独立核查实际文件、数据库、HTTP/UI 和测试；
- 有问题时发定向 REWORK；
- 当前检查点通过但全局任务未完成时，planner 必须把下一检查点写入 `temp.md` 并交还 coder，自动继续；
- 不要求用户再次输入 `$double-planner`；
- state 等待、对方轮次和 `paused_budget` 都是正常调度状态，不得据此结束 Goal。

## 4. 架构原则

1. 继续采用渐进式模块化单体；保留 SQLite、原生 Web 和现有数据，除非真实证据证明无法满足本任务。
2. 动态字段是筛选、多视图、关系、图表和仪表盘的共享基础。
3. 所有视图共享任务数据、字段定义、查询、权限、version 和活动语义，禁止复制多套业务数据。
4. 服务层承载权限与业务规则，HTTP 层保持薄适配器。
5. 所有 mutation 必须进行服务端认证、授权、CSRF、输入验证和适用的乐观并发控制。
6. 关键变化写稳定 action code 和结构化 details。
7. 删除优先软删除；迁移前使用 SQLite backup API 生成一致性备份。
8. 聚合、搜索、通知、附件和实时推送都必须执行权限过滤。
9. 每个检查点形成可运行、可回归、可恢复的版本。
